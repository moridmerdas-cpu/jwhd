# عضویت اجباریه سپر

ربات عمومی، رایگان و **چندگروهیِ** جوین اجباری تلگرام.

## چه چیزی تغییر کرد نسبت به نسخه‌ی قبلی؟

- قبلاً ربات فقط در **یک** گروهِ از پیش تنظیم‌شده کار می‌کرد.
- الان هرکسی می‌تواند ربات را به گروه خودش اضافه و ادمین کند؛ همان لحظه خودش
  «مالک آن گروه» در ربات می‌شود و از پیوی ربات (/start) می‌تواند جوین
  اجباری‌های مخصوص همان گروه را تنظیم کند (کانال/گروه/ربات، متن هشدار و تاییدیه،
  زمان حذف خودکار پیام هشدار).
- آیدی عددی `8977934490` **مالک اصلیِ کل ربات** است. هر آیتمی که این آیدی از
  منوی «📡 آیتم‌های سراسری» اضافه کند، به‌صورت خودکار در جوین اجباریِ **همه‌ی
  گروه‌های ربات** (قدیم و جدید) قرار می‌گیرد. مالک اصلی هم‌چنین از منوی «🗂 همه‌ی
  گروه‌ها» به تنظیمات هر گروهی هم دسترسی دارد (پشتیبانی/نظارت).
- بقیه‌ی مالکانِ گروه فقط گروه خودشان را می‌بینند و مدیریت می‌کنند.

## راه‌اندازی

1. `pip install -r requirements.txt`
2. یک پروژه در Supabase بسازید و کوئری‌های زیر را در SQL Editor اجرا کنید:

```sql
create table if not exists groups (
    id bigint primary key,
    owner_id bigint,
    title text,
    warn_text text,
    joined_text text,
    delete_seconds double precision not null default 5,
    created_at timestamptz not null default now()
);

create table if not exists items (
    id bigint generated always as identity primary key,
    group_id bigint references groups(id) on delete cascade,
    kind text not null default 'channel',
    chat_id text not null,
    title text not null,
    invite_link text not null,
    created_at timestamptz not null default now()
);

create table if not exists bot_starts (
    bot_username text not null,
    user_id bigint not null,
    started_at timestamptz not null default now(),
    primary key (bot_username, user_id)
);
```

> اگر از نسخه‌ی قبلی (تک‌گروهی) مهاجرت می‌کنید، داده‌ی جدولِ قدیمیِ `channels`
> هم‌ساختار نیست؛ ساده‌ترین راه ساختن از صفر همین سه جدول بالاست و افزودن دوباره‌ی
> آیتم‌ها از پنل مدیریت.

3. متغیرهای محیطی را تنظیم کنید:
   - `BOT_TOKEN` — توکن ربات از BotFather
   - `SUPABASE_URL`, `SUPABASE_KEY` — از تنظیمات پروژه‌ی Supabase (کلید service_role)
   - `WEBHOOK_URL` — آدرس عمومیِ سرویس (روی Render به‌صورت خودکار از `RENDER_EXTERNAL_URL` خوانده می‌شود)
   - `WEBHOOK_SECRET` — یک رشته‌ی دلخواه ثابت (اختیاری ولی توصیه می‌شود)
   - `EXTRA_OWNER_IDS` — اختیاری، آیدی عددی مالکان اصلیِ اضافه، جدا با کاما (مالک اصلیِ ثابت `8977934490` همیشه فعال است)
4. `python bot.py`

## استفاده

1. ربات را در گروه خود **ادمین** کنید (با دسترسی حذف پیام، حداقل).
2. همان کاربری که ربات را ادمین کرده، به پیوی ربات برود و `/start` بزند →
   «👥 گروه‌های من» → گروه مدنظر → مدیریت آیتم‌ها/متن‌ها/زمان حذف.
3. برای اینکه ربات بتواند عضویت در کانال/گروهِ دیگر را چک کند، باید در آن
   کانال/گروه هم ادمین باشد.

## مصرف اینترنت

- ربات کاملاً **وبهوکی** است؛ هیچ polling ای در کد وجود ندارد (که خودش بزرگ‌ترین
  منبع مصرف بی‌جهتِ اینترنت در ربات‌های تلگرامی است).
- نتیجه‌ی تنظیمات گروه‌ها، آیتم‌ها و بررسی عضویتِ هر کاربر، به‌مدت چند ثانیه تا چند
  دقیقه کش می‌شود؛ یعنی در هجوم پیام هم به ازای هر پیام یک درخواست جدید به
  تلگرام/Supabase زده نمی‌شود.
- هر چک عضویت فقط یک پاسخ کوچک JSON (چند صد بایت) است، نه فایل یا مدیا.
- با این معماری، برای یک ربات با چند ده گروه و ترافیک معمولی، مصرف ماهانه
  به‌طور معمول چند صد مگابایت تا حداکثر ۱-۲ گیگابایت می‌ماند؛ یعنی زیر سقف ۵
  گیگابایتِ درخواستی به‌راحتی جا می‌شود. اگر تعداد گروه‌ها/پیام‌ها بسیار زیاد شد
  (چند صد گروه پرترافیک)، مقدار `CACHE_TTL_SECONDS` و
  `MEMBERSHIP_OK_TTL_SECONDS` در ابتدای `bot.py` را بزرگ‌تر کنید تا تماس‌ها
  کمتر شوند.

## محدودیت‌های شناخته‌شده

برای ساده و سبک نگه‌داشتنِ نسخه‌ی چندگروهی، قابلیت‌های «تعرفه‌ی ممبر» و
«انقضای زمانی خودکارِ هر آیتم» که در نسخه‌ی تک‌گروهیِ قبلی وجود داشت، در این
نسخه حذف شده‌اند (چون نیاز به چک دوره‌ای تعداد اعضا دارند و مصرف اینترنت و
پیچیدگی را بالا می‌برند). اگر لازم‌شان دارید بگویید تا به همین ساختار
چندگروهی اضافه شوند.
